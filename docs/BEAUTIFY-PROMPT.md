# 任务：把 DSH Office TV 的电视页面改造成「可爱的像素办公室」

## 你是谁

你是资深 2D 像素美术 + 前端游戏开发，擅长 Canvas 2D 和"低成本但高级"的像素场景。
你在一个真实仓库里工作，要直接改代码、跑起来、截图验证，不要只给建议。

## 项目是什么

**DeepSeek agent Office**：Mac 上跑一个零依赖 Node bridge，把 DeepSeek Harness（DSH）的
会话状态变成一间"深夜办公室"；Android TV APK 用全屏 WebView 播放 `bridge/web/` 页面，
给小朋友看"AI 小人上班"，长按遥控 OK 可以和像素鲸鱼娘互动。

先读：`README.md`、`PLAN.md`、`CONTRACT.md`，再动手。

## 现在的实现

- 页面：`bridge/web/index.html` + `app.js`（约 100KB 单文件）+ `style.css`。
  **零构建、零依赖、无外链、无网络字体**，全部 Canvas 2D 程序化绘制。
- 设计稿：`#stage` 固定 1920×1080，按窗口等比缩放居中（1280×720 / 4K 都不拉伸）。
- 场景：2 行 × 3 列 = 6 个工位，每个工位对应一个真实 DSH 会话；右侧站着鲸鱼娘；
  左上 HUD（直播状态/会话数/时钟），底部操作提示条。
- 数据：每 2 秒 `GET /api/state`（schema 见 `CONTRACT.md` 第 3 节）：会话标题、status
  （working/waiting/success/idle/error）、activity（"正在调用工具 · 第 N 步"）、todo 进度、团队。
- 鲸鱼娘：`GET /api/pet` 拿 13 个动作 clip × 241 帧（412×344 webp，24fps），
  `GET /pet/<clip>/<frame>` 取帧。**必须继续用这套帧**（MIT 素材，不要重绘/替换形象）。
- 交互：`window.DshTv.onKey('ok' | 'long_ok' | 'back' | 'up' | 'down' | 'left' | 'right' | 'menu')`；
  短按戳鲸鱼娘、长按开「和鲸鱼娘聊聊」面板、方向键移动观察光标、BACK 分层关闭。
- 语音：面板回答优先播 `GET /api/tts?text=`（edge-tts 中文神经语音），失败回退
  `DshTvNative.speak(text)`，字幕永远显示。
- 目标设备：小米盒子5（HyperOS，2GB RAM，4K 输出，遥控器），WebView = Chrome 100+。

## 用户的抱怨（原话）

1. 「页面有点儿丑，不如像素风那个可爱。」
2. 「角色也没有走来走去，只有睡觉。」

翻译成目标：**视觉要有统一、精致、可爱的像素游戏质感；办公室要有生命感，小人真的在走动、干活、摸鱼。**

## A. 视觉要求：往「可爱的像素风」改

参考气质（只学气质，不抄素材）：
- `Thunderunruly/agent-office`（dsh-pixel-office）的像素写字楼；
- `pablodelucca/pixel-agents` 的工位与小人；
- Stardew Valley 深夜室内的光影和细节密度。

**配色**（和鲸鱼娘统一，别跑偏）：
- 底色 / 深夜墙：`#0b1220` `#152241` `#1e3160`
- 奶油 / 纸：`#f2e8d5` `#e6d7bb`
- 金色高光：`#d9a441` `#f2b94b`
- 青色点缀：`#4aa3b8` `#6fd0e0`
- 鲸鱼娘的蓝发作为画面"最亮的一块"，周围保持暗，让她跳出来。

**具体做法**：
1. **统一像素网格**：选 4px 或 6px 网格，所有家具/墙面/地板/灯对齐网格；线条 1~2 格宽，
   斜角用楼梯式像素，不要抗锯齿圆角。
2. **光影层次**：台灯暖光池、窗外月光/城市光、显示器冷光、地板反光、墙角暗部；
   用径向渐变的暖色叠加（Canvas 里做好一次缓存，别每帧重算）。
3. **氛围**：飘浮尘埃粒子（慢速、低透明度）、窗外雨丝或雪、远景鲸鱼剪影缓慢游过、
   偶尔闪电/飞机灯。
4. **生活细节**：绿植轻微摆动、挂钟秒针、饮水机气泡、睡着的小猫、鱼缸冒泡、
   霓虹灯牌 `DSH`（呼吸闪烁）、墙上海报/便利贴、桌角咖啡杯冒热气。
5. **工位铭牌重做**：像素风小铭牌（1px 深色描边 + 2px 内高光 + 小三角指向小人），
   信息层级：**标题 > 状态 > 步数**；标题超长用省略号；working 时铭牌有呼吸光。
6. **鲸鱼娘**：素材帧不变，但——
   - 脚下平台做成发光水波纹（周期性扩散）；
   - 加柔和投影和呼吸缩放（1.0 → 1.015）；
   - 气泡改成像素对话框（2px 描边 + 小尾巴 + 打字机），不要现在的圆角白卡；
   - 她偶尔"看向"正在 working 的工位（眼睛区域加一个高光偏移即可，不要 P 图）。

**避免**：扁平色块、大圆角、阴影模糊、渐变发光堆砌、PS 剪贴画感、字号小于 20px 的正文。

## B. 行为要求：小人要「活」起来

给每个工位的小人一个状态机，由 `/api/state` 的 `status` + `activity` 驱动：

| 状态 | 行为（要有可见动作） |
|---|---|
| `working` | 坐在工位敲键盘（2 帧打字循环 + 屏幕滚动代码 + 头顶小齿轮） |
| `thinking` | 站着托下巴/看屏幕，头顶思考气泡（`…` 或 `?`） |
| `waiting` | 站起来左右张望，或走到饮水机/窗边等，10~20 秒回工位 |
| `success` | 举手蹦一下（1.5 秒），屏幕闪绿光，然后回工位 |
| `idle` | **随机**：走动、去咖啡机、看窗外、摸猫、打瞌睡（睡觉只能占 idle 的一部分时间） |
| `error` | 快速左右抖动 0.8 秒 + 红色感叹号气泡，然后垂头站着 |

行为细则：
- 办公室用 **32×32 像素格子**做简单寻路（BFS/A* 都行），不能穿墙、穿桌子、互相重叠；
- 走动用 2 帧 walk 循环（程序化像素小人 16×24 或 24×36），带地面阴影和 ±1px 上下浮动；
- 每个小人给一点"性格"：速度 40~70px/s、停留 3~10 秒、偏好地点（咖啡机/窗边/书柜），
  让画面看起来自然随机、但不乱；
- **同一时刻最多 4 个小人在走动**；其余在工位或固定点做小动作；
- 空工位显示"空工位"铭牌（可以有小猫睡在上面）；
- 关键验收：**随便截 10 秒，至少能看到一次走动或交互**。

## C. 不能破坏的东西（硬约束）

1. 接口：`/api/state`、`/api/pet`、`/api/chat`、`/api/tts`、`window.DshTv.onKey` 的动作集合、
   `DshTvNative` 方法、`onVoiceResult`。**不要改 `bridge/*.mjs`**。
2. 现有交互：短按戳、长按开面板、方向键观察光标、BACK 分层关闭、断线等待画面 + 自动重连、
   `?mock=1`（离线演示）、`?panel=1`（截面板态）、`?cursor=N` 调试参数。
3. 性能预算（2GB 盒子）：30fps 上限；静态背景只画一次到离屏 canvas；鲸鱼娘帧环形缓冲
   ≤24 帧 × LRU 2 clip；不要每帧 `shadowBlur`/`filter`；文字用系统字体。
4. 台词字符串尽量别改（已按现有文案预生成 TTS 缓存）；必须改时保持语气一致。
5. 不要引入任何外部依赖、CDN、字体文件、图片文件；所有新美术都程序化绘制。
6. 中文在 1280×720 下 3 米外要能读；不要出现文字溢出/换行炸裂。

## D. 怎么跑、怎么验

```bash
# 在仓库根目录
./tools/serve.sh                      # 起 bridge（会打印电视地址）
open "http://127.0.0.1:8765/tv"       # 真实数据
open "http://127.0.0.1:8765/tv?mock=1" # 无 DSH 状态时的假数据演示
```

验收（自己跑，别让用户跑）：
- Chrome headless / CDP 截图：1920×1080、1280×720 各一张；控制台 **0 error**；
- 用 `window.DshTv.onKey('ok'|'long_ok'|'up'|'down'|'back')` 全走一遍，面板/打字机/断线恢复正常；
- 帧率自测：Chrome Performance 或 `requestAnimationFrame` 计数，平均 ≥28fps；
- 截图存到 `assets/`（覆盖现有同名截图），并更新 `README.md` 里的展示图。

## F. 验收标准（用户视角）

- 第一眼："好可爱，想多看一会儿"，像素质感统一，不像 PPT / 扁平插画；
- 10 秒内能看到小人在走动/串门/摸鱼；
- 鲸鱼娘和房间有互动（光、影、气泡、眼神）；
- 1280×720 下文字清楚；
- 没有卡顿、没有报错、没有外网请求。
